## Review history — read this before touching the threshold logic

Two independent review rounds failed. Both failures are instructive.

**Round 1 — real security defect.** `verify_link` passed the *message's own* `LnProvenWeight` into
`verify_all_reveals`, which used one value as both the signed preimage input and the proven-weight
bound. Because the message is authored by the proof builder, the bound was attacker-chosen: the minimum
passing `SignedWeight` collapsed from ~2e15 to **4** at `ln = 0`. Fixed by composing the individual
checks and passing the **authenticated previous-interval** value.

**Round 2 — failed on my claims, not the code.** The A5 path was cleared by reproduction, but the
handover said `stateproof.py`'s docstring had been corrected and **I had never touched that file**.
`verify_signed_weight_threshold` still certified `w = 4` at `ln = 0` as a documented public API, the
fixture-capture script could not regenerate its own fixture, and the counts did not reproduce. Fixed in
`a3f8477`. Lesson: the cryptographic work survived review; the claims about the work did not.

## Traps that have already cost time

1. **The venv imports the wrong tree.** `cache/scratch/proofpack-a4/venv` resolves
   `avm_proofpack` from `C:/algo/worktrees/avm-proofpack-stateproof-a4/src`, **not** this checkout.
   Always export `PYTHONPATH=C:/algo/avm-proofpack/src` and print
   `os.path.dirname(avm_proofpack.__file__)` to confirm. A capture "succeeded" against unpatched code
   because of this and silently produced no new field.
2. **State proofs exist only at rounds divisible by 256**, and nodes retain only the last ~2 intervals.
   A transaction at an arbitrary round cannot be captured. Pick a txn in a round where
   `/v2/stateproofs/{round}` actually returns, or capture immediately.
3. **The indexer returns oldest-first.** `?limit=N` without a round filter gives early-ledger rounds
   that every node has pruned. Use `min-round` or an exact `round`.
4. **`state_proof_msgpack_b64` IS the proof**, despite reading like a message; `state_proof_message` is
   the structured message. Misreading this inverted a whole diagnosis and produced a duplicate key that
   doubled bundle size. Check with `mpack.decode` before assuming.
5. **A mutation-test leftover sat uncommitted in a file under review** — a deleted
   `isinstance(link, ChainLink)` guard. Always `git status` the worktree before handing a file to a
   reviewer, and restore the tree before mutating.

## A6 — the remaining six steps

Full plan in `A6-stake-attested.md`. Summary:

1. ~~capture carries the full `StateProof`~~ — **done**
2. verify `state_proof_message_hash` matches what the reveals sign
3. verify each reveal's Falcon-1024 signature (`verify_reveal`, KAT-validated)
4. verify ephemeral-key membership against the `"KP"` leaf at `round - round % KeyLifetime`
5. verify signing weight against the **authenticated previous-interval `ln_proven_weight`**, never the
   message's own
6. run A4 coin selection with the authenticated participants commitment
7. only then emit `stake_attested`; fail closed to `structural`/`corroborated` at every earlier step

**Definition of done includes negative controls**: a flipped signature byte, and a substituted message
`ln`, must both fail. Without both, the tier is unproven — and this codebase has already shipped one
vacuous security test that passed for an unrelated reason.

## Flaky test

`tests/server/test_service.py::test_distinct_keys_run_in_parallel` fails under full-suite load but
passes in isolation (0.19s, 0.21s). It mocks `capture`, so it is unrelated to the state-proof work. It
is a timing-sensitive parallelism test and should be made deterministic rather than ignored.
